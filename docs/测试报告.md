# 测试报告 — v1.1.0

- 测试日期：2026-10-24
- 程序版本：v1.1.0
- 测试环境：Windows 11 + Python 3.14.7 + Microsoft Office 2016+（用于 PDF 渲染目检）

本次发布的验证目标是「所有交互开关都真实存在且有效」——包括 v1.0 就有的 5 个版式开关，
以及 v1.1 新增的「自动排版」「优化文字内容」「调整图片尺寸」。

## 一、自检（自动化）

### 1. 源码自检

```bash
python src/main.py --selftest --samples samples --out tests/out
```

| 项目 | 结果 |
| --- | --- |
| 通过 | **334** |
| 失败 | 0 |

覆盖范围：

- 10 个"故意排得乱"的样本（8 个 Word + 2 个 Excel）× 8 套模板 = 80 次优化
- 开关组合：全开 / 全关 / 仅改字体 / 仅内容 / 仅图片 / 排版总开关关闭
- 每个产物的以下断言：
  - 未勾选「优化文字内容」时，处理前后正文文本指纹（w:t / 单元格值）完全一致 → **内容零改动**
  - OOXML 包结构完整、必需部件齐全、关键父元素子节点顺序合规（避免 Word 报"文件已损坏"）
  - 关闭"分页"开关时，正文段落与 Heading 1~3 / Title 样式均无分页设置
  - 关闭「自动排版」时，段落格式与字体指纹与源文件完全一致
  - 关闭「调整图片尺寸」时，图片宽度与源文件一致；开启时超宽图被缩进版心、小图标不放大
  - Excel：表头底色、边框、列宽、打印设置、冻结窗格、页码页脚均已写入
- 非法输入拒绝：缺扩展名、非 OOXML、空 zip、伪造扩展名、`.doc` / `.xls` 老格式
- 输出文件名冲突时自动加 `(2)` / `(3)` 后缀，不覆盖既有文件

## 七、已知限制

1. `.doc` / `.xls` 老二进制格式不支持（会明确提示另存为新格式）。
2. 「优化文字内容」是规则驱动的删减（词表 + 正则），不做语义改写：能删赘语、虚词、冗余标点，
   但**不会**重写句子结构。需要"润色"效果时仍需人工处理。
3. SmartArt、图表、公式对象的尺寸不调整；图片只处理 inline / 浮动图片与 Excel drawing 图片。
4. 复杂合并单元格的 Excel 表，自动列宽只做保守估计，个别列可能仍需手工微调。
5. 招标 / 投标模板正文未强制两端对齐（保留原文对齐方式，避免拉伸字间距影响印刷观感）。
6. 拖放功能依赖 `tkinterdnd2`，若运行环境缺少 `tkdnd` 库会退化为「添加文件…」按钮方式（界面会提示）。
